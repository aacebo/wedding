# Phase 04 — LLM Extraction Pipeline (OpenAI)

## Goal
Turn each ingested `comm_source` into structured, actionable data — todos,
timeline events, and deadlines — using the OpenAI API. Idempotent, deduplicated,
and cost-aware.

## Scope
- New workspace crate `crates/llm` with an OpenAI client behind a trait
  (`LlmExtractor`) so the provider is swappable later.
- An extraction service that processes unprocessed `comm_sources` and persists
  structured results linked back to their source.

## Extraction contract
- Prompt the model (JSON mode / structured outputs) to return, per source:
  - **todos:** `title`, `owner` (nullable), `due_date` (nullable), `priority`
    (`low`|`med`|`high`), `confidence` (0–1), `notes`.
  - **timeline_events:** `title`, `date`, `category` (e.g. venue, catering),
    `confidence`.
  - **deadlines:** `title`, `due_date`, `severity`, `confidence`.
- System prompt treats email/doc text as **untrusted**: it must not follow
  instructions embedded in the content (prompt-injection defense).
- Low-confidence items are stored but flagged for human review in the UI.

## Data model (new migration `006_create_admin_items.sql`)
- `todos_admin`: `id`, `source_id FK`, `title`, `owner`, `due_date`, `priority`,
  `status` (`open`|`done`|`dismissed`), `confidence`, `created_by`
  (`ai`|`human`), `created_at`, `updated_at`.
- `timeline_events`: `id`, `source_id FK NULL`, `title`, `event_date`,
  `category`, `confidence`, `created_by`, timestamps.
- `deadlines`: `id`, `source_id FK NULL`, `title`, `due_date`, `severity`,
  `status`, `confidence`, `created_by`, timestamps.
- `llm_runs`: audit of each extraction (source_id, model, prompt/response
  tokens, cost estimate, status, error).

## Config additions
- `openai_api_key`, `openai_model` (default e.g. `gpt-4o-mini`),
  `llm_max_batch` (cost cap per run).

## Idempotency & dedupe
- Only process sources where `processed_at IS NULL`; set `processed_at` after.
- Dedupe/merge new items against existing ones (fuzzy match on title + due_date
  per source) so re-runs don't duplicate; never overwrite human edits.

## Routes
- `POST /admin/extract` → process pending sources (bounded by `llm_max_batch`),
  returns counts.
- (Later wired into the scheduler in Phase 07.)

## Acceptance criteria
- Running extraction on seeded sources yields todos/events/deadlines linked to
  their sources.
- Re-running does not duplicate items or clobber human edits.
- Injected instructions in email bodies are ignored.
- Token usage/cost recorded per run.

## Out of scope
- Displaying/editing items (Phase 05); reminders (Phase 06).
