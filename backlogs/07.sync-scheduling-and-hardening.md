# Phase 07 — Sync Scheduling & Hardening

## Goal
Make the admin hub run itself: periodically ingest + extract + generate
notifications in the background, with the security, secrets, and operational
polish needed for production on Render.

## Scope
- A single reusable pipeline pass (ingestion → extraction → notification
  generation) driven **on a schedule by a Render cron job**, plus the manual
  `/admin/sync` + `/admin/extract` endpoints, all calling the same code.
- Secrets wiring, encryption review, audit logging, error surfacing, docs.

## Scheduling — Render cron job (chosen over an in-process interval)
A periodic batch (ingest → extract → notify) is a better fit for a cron job than
an always-on in-process `tokio` loop:
- **Decoupled** from the web dyno — a slow Gmail/OpenAI call can't tie up request
  handling or the web DB pool.
- **No duplicate-loop hazard** if the web service ever autoscales to >1 instance.
- Render gives **free overlap protection** (skips a run while the prior is going)
  and **run history** in the dashboard, and bills only for run time.

Implementation:
- Extract the pass into a shared `pipeline::run_once(ctx, trigger)`:
  1. For each linked account: incremental Gmail + Drive sync (Phase 03).
  2. Bounded LLM extraction on new sources (Phase 04).
  3. Regenerate notifications (Phase 06).
- A one-shot `sync-once` CLI subcommand (`/app/api sync-once`) runs a single pass
  and exits — this is what the cron job invokes.
- Overlap protection via a Postgres **advisory lock** (`pg_try_advisory_lock`) so
  a scheduled run and a manual trigger can't overlap; the run is skipped if the
  lock is held. Backoff is inherent to the cron cadence.
- A `sync_runs` audit table (trigger, status, counts, error, started/finished).

## Secrets & deploy
- Add a `type: cron` service to `render.yaml` (`schedule: "*/30 * * * *"`,
  `dockerCommand: /app/api sync-once`) sharing the DB and secrets.
- Declare secret env vars with `sync: false` (prompted at blueprint creation):
  `GOOGLE_CLIENT_ID/SECRET`, `GOOGLE_REDIRECT_URI`, `TOKEN_ENCRYPTION_KEY`,
  `OPENAI_API_KEY`, and `ADMIN_ALLOWLIST`; generate `SESSION_SECRET`.
- Provide a local `.env.example`; never commit real secrets.
- Set the production `GOOGLE_REDIRECT_URI` to `https://baicebo.com/admin/auth/
  google/callback` and register it in the Google Cloud console.

## Hardening
- Review OAuth scopes are read-only and minimal.
- Confirm tokens + any sensitive fields are encrypted at rest; keys from env.
- Ensure `/admin/*` is uniformly behind `AdminSession` (add an integration test).
- Surface sync/extraction errors in the dashboard (last run status + message).
- Structured logging (no tokens / PII / secrets in logs).

## Acceptance criteria
- With the cron job enabled, new emails/docs appear as todos/timeline/notifications
  without manual action.
- No overlapping runs (advisory lock); failures are recorded and visible in the UI.
- All secrets sourced from env; none committed; scopes read-only.
- End-to-end pass: link accounts → scheduled sync → dashboard reflects reality.
