# Phase 05 — Admin Dashboard UI

## Goal
Give the couple a clean, single-pane dashboard to see aggregated
communications, work their todos, and view the wedding timeline — with the
ability to correct anything the AI got wrong.

## Scope
- Askama templates under `templates/admin/` using the site's existing
  Tailwind (CDN) + htmx + Alpine setup.
- Read + CRUD routes for todos, timeline events, deadlines, and the inbox.

## Views
- **Inbox** (`/admin/inbox`): aggregated `comm_sources`, filter by provider /
  account / date; each row links to the original Gmail/Drive URL.
- **Todos** (`/admin/todos`): grouped by status/owner/due date; inline
  complete / edit / dismiss via htmx; add-todo form (manual, `created_by=human`);
  low-confidence AI items visually flagged for review.
- **Timeline** (`/admin/timeline`): chronological list + light calendar-style
  grouping of `timeline_events` and `deadlines`.
- **Source drill-through:** each todo/event/deadline shows and links to the
  originating source (email/doc) for context.

## Routes
- `GET /admin` → dashboard summary (counts, upcoming deadlines, recent inbox).
- `GET /admin/inbox`, `GET /admin/todos`, `GET /admin/timeline`.
- `POST /admin/todos`, `PATCH /admin/todos/{id}` (status/fields),
  `DELETE /admin/todos/{id}`.
- `POST/PATCH/DELETE` equivalents for `timeline_events` and `deadlines`.
- htmx partial endpoints returning fragments for inline updates.

## Design notes
- New `templates/admin/base.html` (from Phase 01) with an admin nav (Dashboard /
  Inbox / Todos / Timeline / Sync). No public site nav.
- Reuse the site palette (cream/ink/accent) for visual consistency.
- All routes behind the `AdminSession` extractor.
