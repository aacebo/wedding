# Phase 03 — Gmail + Drive Ingestion

## Goal
Pull communications from both linked Google accounts (Gmail messages and Drive
files) and normalize them into a single `comm_sources` table that later phases
process. Incremental and deduplicated.

## Scope
- Gmail + Drive API clients in `crates/google` (built on Phase 02 tokens).
- A normalized `comm_sources` store.
- A manual "Sync now" endpoint (scheduling deferred to Phase 07).

## API usage
- **Gmail:** `users.messages.list` (optionally filtered by a wedding label/query
  such as `newer_than:1y` and/or specific labels), then `users.messages.get`
  (format=full) for headers + body. Incremental via `historyId` /
  `users.history.list`.
- **Drive:** `files.list` (filter by folder(s) or query), `files.get` /
  `files.export` for Google Docs → text. Incremental via `changes` page tokens
  (`startPageToken`).

## Data model (new migration `004_create_comm_sources.sql`)
`comm_sources`:
- `id UUID PK`, `account_email TEXT`, `provider TEXT` (`gmail`|`drive`),
  `external_id TEXT`, `kind TEXT` (`email`|`doc`|`file`),
  `sender TEXT NULL`, `title TEXT` (subject/filename), `snippet TEXT`,
  `body_text TEXT`, `url TEXT`, `occurred_at TIMESTAMPTZ`,
  `raw JSONB`, `processed_at TIMESTAMPTZ NULL`,
  `created_at`, `updated_at`.
- `UNIQUE (provider, external_id)` for dedupe.
- Index on `processed_at` (for the Phase 04 worklist) and `occurred_at`.

`sync_state` (per account/provider cursor):
- `account_email`, `provider`, `cursor TEXT` (historyId / drive page token),
  `last_synced_at`, `PRIMARY KEY (account_email, provider)`.

## Routes
- `POST /admin/sync` → runs Gmail + Drive sync for all linked accounts, returns
  counts (new/updated/skipped).
- `GET /admin/sync/status` → last sync time + cursor per account/provider.

## Implementation notes
- **Gmail incrementality** uses an epoch-seconds high-water mark fed to the
  `after:` search operator (stored as the `sync_state.cursor`), rather than the
  History API — simpler and robust to expired history ids. The
  `UNIQUE (provider, external_id)` constraint absorbs boundary-second overlap.
- **Drive incrementality** uses the changes feed: first sync seeds via
  `files.list` (Google Docs only) then stores `startPageToken`; later syncs poll
  `changes.list` and advance to `newStartPageToken`. Removed files are deleted
  from `comm_sources`.
- A "Sync now" button on the `/admin` dashboard calls `POST /admin/sync`.

## Acceptance criteria
- "Sync now" populates `comm_sources` from both providers without duplicates.
- Re-running only fetches deltas (cursors advance).
- Google Docs are stored as readable `body_text`.

## Out of scope
- Turning sources into todos (Phase 04); automatic scheduling (Phase 07).
