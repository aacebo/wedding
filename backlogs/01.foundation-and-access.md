# Phase 01 — Foundation & Hidden `/admin` Access

## Goal
Stand up a hidden `/admin` area gated behind an authenticated session, plus the
scaffolding every later phase builds on. Unauthenticated visitors get a **404**
(so the page stays "hidden"), not a login-looking 401.

## Scope
- New workspace crate `crates/admin` for admin-only domain logic, isolated from
  the public site code in `bins/api`.
- A signed-cookie session layer so a signed-in planner stays logged in.
- An access allowlist of exactly the two Google account emails (from config).
- The `/admin` route shell + `templates/admin/base.html` distinct from the
  public `base.html` (no public nav, own styling).

## Design notes (fits existing patterns)
- Mirror the existing layout: routes in `bins/api/src/routes/admin/`, data types
  + storage in `crates/storage`, templates in `bins/api/templates/admin/`.
- Register an `admin` route module in `main.rs` alongside the others.
- Reuse `RequestContext`; add an `AdminSession` extractor that reads a signed
  session cookie and returns 404 when absent or not allowlisted.
- Config additions in `bins/api/src/config.rs`: `admin_allowlist` (comma-sep
  emails) and `session_secret` (cookie signing key), both from env.

## New dependencies (workspace)
- `actix-session` (cookie session backend) or a signed cookie via actix-web's
  `cookie` crate.
- Keep Google/LLM crates out of this phase.

- Unauthenticated `/admin` returns 404.
- With a valid session cookie for an allowlisted email, `/admin` renders the
  placeholder dashboard.
- `cargo build` and `cargo clippy` clean; public routes unaffected.
